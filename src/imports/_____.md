# 软件规划书（TaskFlow）

## 1. 产品愿景与定位

TaskFlow 是一款以「任务流」为核心的效率应用。  
它不以日历日期为中心，而是以「当前最该完成的下一项任务」为核心，帮助用户降低选择成本并持续推进执行。

### 1.1 愿景

让用户每天打开应用后，不需要思考「我该做什么」，而是直接进入「我现在就做这个」的状态。

### 1.2 产品定位（一句话）

一个强调流式推进、即时反馈和低认知负担的个人任务管理工具。

### 1.3 差异化价值

1. **任务优先于日期**：默认首页是任务流，不是月/周日历。  
2. **强交互体验**：通过 Figma + ProtoPie 定义前卫、顺滑、可感知的任务推进动效。  
3. **执行导向反馈**：每次完成任务都给出明确反馈，持续强化行动习惯。

## 2. 问题定义与目标

### 2.1 当前痛点

1. Apple 日历更适合事件时间管理，不适合任务执行管理。  
2. Apple 日历与提醒事项的交互体验偏传统，缺乏“推进感”和“流动感”。  
3. 用户面对任务列表容易产生压力和拖延，无法快速进入行动。

### 2.2 产品目标（首阶段）

1. 让用户在 5 秒内明确当前任务。  
2. 让用户能在 2 步内完成关键操作（完成/延后/跳过）。  
3. 提升任务完成率与连续完成天数（streak）。

## 3. 用户画像与核心场景

> 首版建议聚焦单一主用户，先打透再扩展。

### 3.1 主用户画像（MVP）

- 18–35 岁个人效率用户（学生、自由职业者、知识工作者）
- 有大量待办，但缺乏稳定执行节奏
- 希望工具“少管理、多完成”

### 3.2 典型使用场景

1. **晨间启动**：打开应用立即看到“当前任务”，快速进入工作。  
2. **碎片时间推进**：地铁/课间/会议间隙完成短任务。  
3. **晚间复盘**：查看今日完成数、未完成原因和明日首任务。

### 3.3 暂不作为首版重点用户

- 团队协作用户
- 企业项目管理用户

## 4. MVP 功能范围

### 4.1 MVP 功能列表（必须上线）

1. **任务创建**
   - 字段：标题、优先级、截止时间（DDL）、预计时长、标签（可选）
2. **任务流首页**
   - 当前任务卡（主视觉）
   - 下一任务预览
   - 今日待办队列（简版）
3. **任务动作**
   - 完成、延后、跳过、拆分子任务
4. **提醒机制（基础版）**
   - 到期提醒
   - 自定义提醒时间
5. **进度反馈**
   - 今日完成任务数
   - 连续完成天数（Streak）
   - 每日简要复盘提示

### 4.2 MVP 范围外（V2+）

1. 团队协作（分配、评论、文件）  
2. AI 自动拆解与智能排程  
3. 多端实时同步的复杂冲突处理  
4. 高级统计报表与深度数据分析

### 4.3 MVP 成功标准（验收口径）

1. 用户可在 1 分钟内完成「创建任务 → 进入任务流 → 完成任务」闭环。  
2. 首次使用用户可独立完成关键操作，无需教程。  
3. 核心流程无阻塞错误，提醒和状态同步稳定可用。

## 5. 交互与体验设计原则

### 5.1 核心交互原则

1. **单焦点原则**：一屏一个主要任务，降低选择焦虑。  
2. **低步骤原则**：关键动作 2 步内完成。  
3. **即时反馈原则**：操作后 300ms 内有视觉反馈。  
4. **默认可行动原则**：系统优先给出建议下一步。

### 5.2 视觉与动效方向

- 风格关键词：轻量、沉浸、流动、明确  
- 动效关键词：浮现、推进、收束、奖励  
- 交互动线：以纵向流和卡片层级突出“当前任务”

### 5.3 Figma + ProtoPie 设计交付物

1. 信息架构图（IA）  
2. 用户流程图（核心闭环）  
3. 低保真线框（首页/创建/详情/复盘）  
4. 高保真视觉稿（关键页面）  
5. ProtoPie 交互原型（浮现、滑动、完成反馈、提醒反馈）

## 6. 信息架构与核心流程

### 6.1 信息架构（首版）

- 首页（任务流）
- 新建任务
- 任务详情
- 今日进度
- 设置（提醒、偏好）

### 6.2 核心用户流程（Happy Path）

1. 新建任务  
2. 进入任务流并识别当前任务  
3. 执行任务并标记完成  
4. 查看即时反馈与进度更新  
5. 系统给出下一任务

## 7. 版本规划与里程碑

### 7.1 V1（MVP，8 周建议）

1. 第 1–2 周：需求冻结 + IA + 低保真  
2. 第 3–4 周：高保真 + ProtoPie 关键交互  
3. 第 5–6 周：核心功能开发  
4. 第 7 周：联调测试与修复  
5. 第 8 周：小范围内测发布

### 7.2 V2（优化版本）

- 引入更智能的任务排序策略  
- 增加轻量化习惯模块  
- 逐步探索多端同步与协作能力

## 8. 技术与数据要点（首版建议）

### 8.1 技术方向

- 客户端优先（移动端优先体验）
- 本地存储 + 云端备份（分阶段引入）
- 通知系统作为核心能力建设

### 8.2 任务数据模型（简版）

- 任务基础信息：id、title、priority、dueAt、estimateMinutes、status  
- 流程状态：todo / doing / done / snoozed / skipped  
- 行为记录：createdAt、completedAt、snoozedCount

## 9. 指标体系（上线后持续追踪）

### 9.1 核心指标

1. 任务完成率  
2. D1 / D7 留存率  
3. 人均日完成任务数  
4. 提醒响应率（通知点击或动作触发）

### 9.2 体验指标

1. 关键流程完成时长（创建到完成）  
2. 关键操作成功率（完成/延后/跳过）  
3. 新用户首日可用性反馈

## 10. 风险与应对

1. **风险：功能堆叠导致 MVP 失焦**  
   **应对：**坚持 MVP 清单，非核心需求进入 V2 待办池。  
2. **风险：交互动效复杂影响开发节奏**  
   **应对：**先保证核心流程可用，再迭代增强动效层。  
3. **风险：提醒策略打扰用户**  
   **应对：**默认温和提醒，可配置频率与时段。
