# TaskFlow App Store 化后续计划

## 0. 当前状态

Phase 1 和 Phase 2 已完成，不再作为后续待办：

1. 认证安全地基已完成：邮箱格式校验、邮箱验证码、Resend 发信、登录/注册限流、HTTPS、`COOKIE_SECURE=true`、生产 CORS 收敛。
2. 用户数据隔离已完成：session 保存 `userId`，本地任务/统计/同步缓存按 `taskflow:<userId>:...` 命名空间隔离，旧全局缓存会迁移到当前用户命名空间，登出会清除当前用户本地缓存。
3. Phase 3 的基础数据可信度已完成：任务写接口字段校验、普通任务列表排除软删除、`/user/stats` 不再信任客户端覆盖 streak。
4. Phase 3A 已完成：最近删除列表、恢复、永久删除、普通删除软删除化、前端最近删除入口。

后续目标是补齐 Phase 3 的大项，然后进入同步可靠性、UI/UX 和 App Store 发布收口。

---

## Phase 3B: 账号数据管理

### 当前问题

1. App Store 对用户数据管理有明确预期，但当前 App 内还没有数据导出和删除账号入口。
2. 用户表缺少 `deletedAt`、`displayName`、`timezone`、`locale` 等后续账号管理字段。
3. 删除账号需要同时处理任务、统计、refresh session 和本地缓存。

### 解决方案

1. 用户表新增字段：`displayName`、`timezone`、`locale`、`deletedAt`、`lastLoginAt`。
2. 新增 `GET /user/export`：导出当前用户的账号、任务、统计数据 JSON。
3. 新增 `DELETE /user/account`：删除账号，撤销 refresh sessions，并级联删除任务/统计。
4. 前端账号页新增“导出数据”和“删除账号”入口。
5. 删除账号必须二次确认，并明确提示此操作不可恢复。
6. 删除成功后清除本地 session、token 和当前用户本地缓存，回到登录页。

### 验收标准

1. 用户可以下载自己的数据导出文件。
2. 删除账号后无法继续刷新 token 或访问任务 API。
3. 删除账号后重新登录会失败，除非重新注册。
4. 其他用户数据不受影响。

## Phase 3C: 服务端统计可信度完善

### 当前问题

1. `/user/stats` 已不再接受客户端覆盖 streak，但统计仍缺少独立完成事件记录。
2. 当前完成统计依赖任务状态变化和 `todayCount`，多设备/重复请求下仍可能不够精确。

### 解决方案

1. 增加任务完成时间字段 `completedAt`，完成任务时由服务端写入。
2. 可选新增 `TaskCompletionEvent`，用来记录完成事件并支持幂等去重。
3. `/user/stats` 改为基于服务端完成记录计算 `todayCount` 和 `streak`。
4. 客户端完成任务时只提交任务状态，不提交 streak。
5. 防止同一任务重复完成导致重复计数。

### 验收标准

1. 用户无法通过 API 伪造 streak 或 todayCount。
2. 同一任务重复完成不会重复增加今日完成数。
3. 跨设备完成任务后统计保持一致。

## Phase 4: 同步可靠性与冲突处理

### 当前问题

1. 当前同步以本地 dirty task 和远端任务合并为主，缺少明确的操作队列。
2. 重复提交、网络中断、App 重启后的操作去重能力不足。
3. 多设备同时编辑同一任务时，缺少版本冲突判断。
4. 同步状态只区分 `idle/syncing/offline/error`，对用户不够清晰。

### 解决方案

1. 将 dirty task 改为持久化 dirty queue，每个操作包含 `operationId`、`taskId`、`type`、`payload`、`createdAt`。
2. 服务端记录或幂等处理 `operationId`，避免重复提交造成重复创建或重复计数。
3. 每次任务更新提交 `lastKnownUpdatedAt` 或版本号，服务端发现冲突返回 `409`。
4. 客户端收到冲突后提供最小处理方式：保留本机、使用云端、稍后处理。
5. 同步状态细分为：已同步、正在同步、离线待同步、存在冲突、服务器错误。
6. 账号页展示最近同步时间和待同步数量。

### 验收标准

1. 离线创建、编辑、完成、删除任务后重启 App，再联网可正确同步。
2. 同一操作不会因重试被重复执行。
3. 两台设备同时编辑同一任务时，会出现明确冲突提示，而不是静默覆盖。
4. 用户能理解当前数据是否已安全同步到云端。

## Phase 5: UI/UX 与用户交互优化

### 当前问题

1. 错误信息仍有部分直接展示后端英文 message，中英文体验不一致。
2. 账号页功能偏少，缺少数据管理、会话管理、隐私政策入口。
3. 任务创建表单缺少字段级错误提示和更清晰的默认值解释。
4. 删除、同步失败、离线模式等关键状态对用户不够可见。

### 解决方案

1. 错误文案改为错误码映射，所有核心认证、任务校验、同步错误都提供中英文翻译。
2. 密码输入增加强度提示和明确规则。
3. 账号页新增邮箱验证状态、同步状态、数据导出、删除账号、隐私政策入口。
4. 任务表单增加字段级错误，例如标题为空、预估时间过大、提醒时间早于当前时间。
5. 删除任务后提供最近删除入口，不只依赖 toast 撤销。
6. 空状态根据场景区分：新用户引导、当天无任务、筛选无结果、离线无缓存。
7. 同步失败时显示可操作说明，例如“点击重试”“解决冲突”。

### 验收标准

1. 所有核心错误都不是裸英文后端错误。
2. 账号页能完成身份、同步和数据管理相关操作。
3. 任务表单错误能明确定位到具体字段。
4. iPhone SE、标准 iPhone、Pro Max 上没有遮挡、裁切或键盘覆盖关键按钮。

## Phase 6: App Store 发布准备

### 当前问题

1. 隐私政策、账号删除入口、审核测试账号、截图和真实设备测试还需要最终收口。
2. 如果未来开启提醒功能，需要清楚说明通知用途并请求系统权限。
3. 手动 DNS 证书需要续期流程，不能遗忘。

### 解决方案

1. 完成隐私政策页面，内容覆盖邮箱、密码哈希、任务、标签、截止日期、提醒、统计数据和刷新会话。
2. 提供 App 内账号删除入口，并在隐私政策中说明删除周期。
3. 创建 App Store 审核测试账号，确保邮箱已验证且有示例任务数据。
4. 准备中英文截图：任务流、添加任务、日历、搜索筛选、账号设置、空状态。
5. 真实设备测试登录、刷新、登出、离线同步、弱网恢复、账号删除。
6. 记录证书续期日期和操作流程，避免 HTTPS 到期。
7. 如果启用通知，补充本地通知权限说明和系统权限申请时机。

### 验收标准

1. `npm run check` 通过。
2. 后端 migration 可在生产环境部署。
3. 生产 API 使用 HTTPS，cookie 和 CORS 配置符合上线要求。
4. 隐私政策 URL 可访问，且描述与实际数据处理一致。
5. App Store Connect 中的测试账号可用。
6. 审核截图覆盖核心使用流程。

---

## 建议执行顺序

1. Phase 3B：先补账号数据导出和删除账号，满足 App Store 数据管理预期。
2. Phase 3C：再完善服务端统计可信度，避免多设备和重复请求造成统计不准。
3. Phase 4：再做同步队列、幂等和冲突处理。
4. Phase 5：再做 UI/UX 精修和错误文案系统化。
5. Phase 6：最后收口 App Store 材料、隐私政策、测试账号、截图和证书续期。

---

## 总体验收测试清单

1. 数据生命周期测试：删除、最近删除、恢复、永久删除、软删除过期策略。
2. 账号管理测试：导出数据、删除账号、删除后 token 失效、重新注册。
3. 统计可信度测试：重复完成、多设备完成、跨天 streak。
4. 同步测试：离线创建/编辑/完成/删除后重启，再联网同步；多设备冲突处理。
5. UI/UX 测试：中英文、键盘打开、错误提示、验证码流程、账号页、空状态、最近删除。
6. 发布测试：生产 HTTPS、真实设备、隐私政策、审核账号、截图、后端 migration、`npm run check`。

---

## 默认假设

1. 保留“账号必需，支持跨设备同步”的产品定位。
2. App Store v1 不加入团队协作、公开分享、社交功能和广告追踪。
3. 离线可读写继续保留，但必须绑定最近验证过的 `userId`，不能跨用户复用缓存。
4. 生产邮件发送使用 Resend，发件邮箱使用已验证域名下的 `verify@mail.taskflow.top` 或等价地址。
